# חומת אבטחה — אתר עומק

עודכן: 8 באוקטובר 2026 (סקריפט 3, מודולים א' ו-ב').

האתר הוא אתר תדמית עם טופס פנייה בלבד. אין בו חנות, תשלום, הרשמה או אזור אישי. לכן החלק החשוב לשמור עליו הוא **הפניות** (שם, טלפון, אימייל של אנשים אמיתיים) ו**הגישה לניהול התוכן**.

לכל שכבה כתוב מה היא שומרת, ומה היא **לא** שומרת. אף שכבה לא אמורה לעבוד לבד.

### כותרות ותוכן הדף (`next.config.ts`, `src/proxy.ts`, `src/lib/security/csp.ts`)

| שכבה | מה שומרת | מה לא שומרת |
|---|---|---|
| CSP עם nonce ו-strict-dynamic | הרצת סקריפט שהוזרק לדף (XSS) | באג בסקריפט שלנו עצמו |
| דיווח הפרות CSP ל-`/api/csp-report` | נותן סימן מוקדם שמישהו מנסה להזריק. נרשם בלוג בלי פרטי שאילתה | לא חוסם בעצמו, רק מדווח |
| HSTS עם preload | הורדה ל-HTTP לא מוצפן | ביקור ראשון לפני שהדומיין ברשימת preload |
| X-Frame-Options + frame-ancestors | הטמעת האתר בתוך אתר אחר (clickjacking) | — |
| nosniff, Referrer-Policy, Permissions-Policy, COOP, CORP, X-Permitted-Cross-Domain-Policies | ניחוש סוגי קבצים, דליפת כתובות, גישה למצלמה/מיקום, שימוש בקבצים שלנו מאתרים זרים | — |
| `poweredByHeader: false`, בלי source maps בפרודקשן | מסתיר באיזה כלי בנוי האתר ואת הקוד המקורי | זה רק מקשה, לא חוסם |
| `Cache-Control: no-store` על `/api`, `/thanks`, `/studio` | שמירה של מידע אישי במטמון משותף | — |
| מידע לגוגל (JSON-LD) עם `<` מוחלף ב-`\u003c`, ו-nonce | תוכן מ-Sanity לא יכול לסגור את תגית ה-script ולהריץ קוד. זה המקום היחיד שמשתמש ב-`dangerouslySetInnerHTML`, לפי ההנחיה הרשמית של Next.js | — |
| תמונות שיתוף: רק קבצים מ-`public` או מ-`cdn.sanity.io/images` | השרת לא יבקש כתובת שרירותית (SSRF) כשהוא מצייר תמונה | — |
| גודל גוף מקסימלי 64KB לפעולות שרת | שליחת בקשות ענקיות שמעמיסות על השרת | — |

## 3. החלפת מפתחות

החלף מפתח מיד אם יש חשש שדלף, ובכל מקרה פעם בשנה.

| מפתח | איפה יוצרים חדש | הערות |
|---|---|---|
| `SANITY_WRITE_TOKEN`, `SANITY_READ_TOKEN` | sanity.io/manage ← API ← Tokens | למחוק את הישן אחרי שהחדש עובד |
| `SANITY_WEBHOOK_SECRET` | לעדכן גם ב-Vercel וגם בהגדרות ה-webhook ב-Sanity | 32 תווים לפחות |
| `RESEND_API_KEY` | resend.com ← API Keys | |
| `TURNSTILE_SECRET_KEY` | Cloudflare ← Turnstile ← Rotate | |
| `UPSTASH_REDIS_REST_TOKEN` | console.upstash.com ← Reset | |
| `LEAD_IP_SALT` | מחרוזת אקראית חדשה | אחרי החלפה, הגבלת הקצב "שוכחת" כתובות קודמות. זה בסדר |
| `CRON_SECRET` | מחרוזת אקראית חדשה | |
| `WA_ACCESS_TOKEN` | Meta ← Business Settings ← System users ← Generate token | לעדכן גם באתר וגם בבוט. למחוק את הישן |
| `WA_APP_SECRET` (בבוט) | Meta ← App settings ← Basic ← Reset | |

יצירת מחרוזת אקראית (PowerShell):

```powershell
[Convert]::ToBase64String((1..48 | ForEach-Object { Get-Random -Max 256 }) -as [byte[]])
```

אחרי כל החלפה ב-Vercel צריך **Redeploy**, כדי שהשרת יקרא את הערך החדש.

## 4. אם משהו קרה (תגובה לאירוע)

1. **לעצור:** ב-Vercel ← Deployments ← לבחור גרסה קודמת תקינה ← **Promote to Production**. זה מחזיר את האתר אחורה תוך שניות.
2. **לסגור גישה:** להחליף את כל המפתחות מסעיף 3. בחשד לדליפה מ-Sanity, למחוק את כל הטוקנים ב-sanity.io/manage וליצור חדשים.
3. **לבדוק:** לוגים ב-Vercel (חיפוש `"level":"error"` או `"scope":"csp"`), היסטוריית שינויים בסטודיו.
4. **ליידע:** אם דלפו פרטים של פונים, החוק בישראל (תקנות הגנת הפרטיות) מחייב לבדוק אם צריך לדווח לרשות להגנת הפרטיות. לפנות לעורך דין.
5. **לתעד:** מה קרה, מתי, מה תוקן. להוסיף ל-`PROJECT_BRIEF.md`.

## 6. רשימה לאבישי (דברים שרק אתה יכול לעשות)

- [ ] אימות דו-שלבי (2FA) ב: GitHub, Vercel, Resend, Cloudflare, Upstash. (ב-Google כבר יש.)
- [ ] Sanity ← API ← CORS origins: להשאיר רק את `https://my-web-three-blue.vercel.app` ו-`http://localhost:3000`. כשיהיה דומיין, להוסיף אותו.
- [ ] GitHub ← Settings ← Code security: להפעיל **Secret scanning** ו-**Push protection**.
- [ ] GitHub ← Settings ← Branches: כלל על `main` שמחייב שה-CI יעבור לפני מיזוג.
- [ ] Vercel ← Settings ← Deployment Protection: להפעיל על גרסאות Preview.
- [ ] Vercel ← Environment Variables: להוסיף `CRON_SECRET` (מחרוזת אקראית של 32+ תווים, ראו סעיף 3). בלי זה המחיקה האוטומטית לא תרוץ.
- [ ] (אופציונלי) להוסיף `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` ב-Vercel, כדי שמזהי פעולות השרת יישארו יציבים בין גרסאות.
- [ ] Vercel ← Firewall: להפעיל Attack Challenge Mode אם רואים הצפה, ולשקול כלל שחוסם מדינות שאין מהן לקוחות.
- [ ] UptimeRobot (חינם): מוניטור HTTP על `/api/health` כל 5 דקות, עם התראה לאימייל.
- [ ] אחרי העלאה: לבדוק ב-[securityheaders.com](https://securityheaders.com) וב-[Mozilla Observatory](https://developer.mozilla.org/en-US/observatory). היעד: A ומעלה.
